## 什么时候需要本包

这是新项目的推荐入口。配置一次插件后，业务代码只使用 `openSqlite()`，不感知当前是 Web 还是哪个小程序目标。

`@weapp-sqlite/weapp-vite` 将平台差异留在构建和 adapter 层。应用配置一次插件，业务代码在 Web、微信、支付宝、抖音、百度、京东和小红书保持一致。

```ts
import { weappSqlite } from '@weapp-sqlite/weapp-vite'

export default defineConfig({
  plugins: [weappSqlite({
    debug: {
      enabled: process.env.WEAPP_SQLITE_DEBUG === '1',
      devtools: process.env.WEAPP_SQLITE_DEVTOOLS === '1',
      page: { route: '__weapp_sqlite_debug/index/index', configFile: './src/sqlite-debug.config.ts' },
    },
    wasm: {
      variant: 'lite',
      weappPackage: { mode: 'generated-subpackage' },
    },
  })],
})
```

```ts
type SqliteWasmVariant = 'full' | 'lite'

type WeappSqliteWasmPackage =
  | 'main'
  | { mode: 'generated-subpackage', root?: string }
  | { mode: 'existing-subpackage', root: string }
```

默认值为 `full + main`，资源名与旧版本一致。`variant` 对 Web 和全部小程序目标生效；`weappPackage` 只影响微信。自动分包 root 默认是 `__weapp_sqlite__`，生成普通分包、隐藏页、主包 loader 和带所有权标记的 runtime，冲突时构建失败。已有分包必须出现在最终 `app.json.subPackages`，且不能设置 `independent: true`。

自动分包通过 weapp-vite 自动路由写入最终 `app.json`，应用配置可来自 `app.json.ts`、`app.json.js` 或 `app.vue` 中的 `defineAppJson()`；最终清单缺少生成分包时构建失败。静态 `app.json` 可继续使用已有分包模式。full 的 runtime engine 为 `sql.js-wasm`，lite 为 `sql.js-wasm-lite`。

## Runtime

```ts
import { execMany, getMigrationStatus, openSqlite, removeSqlite } from '@weapp-sqlite/weapp-vite/runtime'

const database = await openSqlite({ name: 'app.sqlite', migrations })
await execMany(database, 'INSERT INTO notes (body) VALUES (?)', [['第一条'], ['第二条']])
const status = await getMigrationStatus(database, migrations)
console.log(status.pending)
await database.query('SELECT * FROM notes')
await database.close()

await removeSqlite({ name: 'app.sqlite' })
```

同名并发打开会返回同一应用级连接；已打开连接的 adapter 或迁移函数不一致时抛出 `SQLITE_OPEN_OPTIONS_CONFLICT`。`openSqlite()` 在返回前完成能力探测和迁移。宿主不满足要求时抛出 `SQLITE_RUNTIME_UNSUPPORTED`，引擎初始化失败时抛出 `SQLITE_ENGINE_INIT_FAILED`。

`getSqliteTarget()`、`getSqliteRuntimeInfo()` 和 `getSqliteDatabasePath()` 用于验收与调试信息。高级集成可以从 `@weapp-sqlite/weapp-vite/adapter` 导入 `SqliteRuntimeAdapter` 并通过 `openSqlite({ adapter })` 覆盖内置实现。

runtime 同时导出 `execMany`、`getMigrationStatus`、`SqlitePersistenceError` 和迁移诊断类型；`weapp-sqlite/runtime` 提供相同入口。具体行为见 [Core API](/docs/api/core)，事务和自定义引擎的升级步骤见[升级指南](/docs/upgrading)。

## 数据工作台

```ts
import { defineSqliteDebugWorkspace } from '@weapp-sqlite/weapp-vite/debug'

export default defineSqliteDebugWorkspace({
  databases: [
    { databaseName: 'app.sqlite', migrations },
    { databaseName: 'analytics.sqlite', migrations: analyticsMigrations },
  ],
  defaultDatabase: 'app.sqlite',
})
```

`debug: boolean` 仍兼容并映射到默认路由与配置文件。调试构建生成带所有权标记的 TS/WXML/SCSS/JSON 页面；目标目录已有用户文件时直接失败，不覆盖。Web 将其注册为懒加载路由，小程序将其注册为独立分包。

工作台自动复用当前目标 adapter 的数据库、快照和文件交付能力。启用 `devtools` 后可在独立 Devframe 面板中选择运行实例和数据库，支持 Web WebSocket 与微信 `wx.connectSocket`。watch 期间服务和 runtime token 复用，断线中的写操作不会重放；生产构建通过编译常量排除 route、通信桥、凭证、写 SQL、CSV/JSON codec、导入逻辑和 `saveFileToDisk` / `shareFileMessage` / `chooseMessageFile`。

面板自动发现的数据库会沿用该运行实例 `openSqlite()` 已注册的迁移定义。即使数据库没有显式写入 `databases` 配置，迁移诊断仍会比较真实连接中的历史与应用实际使用的版本；外键诊断同样读取该连接的约束和 `foreign_key_check` 结果。

面板 SQL 历史按数据库隔离并保留最近 50 条，执行计划通过 `EXPLAIN QUERY PLAN` 和参数绑定生成，不执行原 SQL。独立宿主也可以从 `@weapp-sqlite/devtools` 导入 `startSqliteDevtoolsServer()`；它返回一次性认证 URL、runtime WebSocket endpoint 和 `close()` 生命周期方法。

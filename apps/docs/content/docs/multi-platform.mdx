`examples/weapp-vite-multi-platform` 使用一份 `openSqlite()` 业务代码构建 Web 与六个小程序目标。每个平台仍单独生成产物，不能把 Web 产物直接当作小程序产物使用。

## 我该构建什么

统一示例的目标构建命令如下：

| 目标 | 命令 | 产物目录 |
| --- | --- | --- |
| Web | `pnpm --filter weapp-sqlite-demo-weapp-vite build:web` | `examples/weapp-vite-multi-platform/dist/web` |
| 微信 | `pnpm --filter weapp-sqlite-demo-weapp-vite build:weapp` | `dist/weapp` |
| 支付宝 | `pnpm --filter weapp-sqlite-demo-weapp-vite build:alipay` | `dist/alipay` |
| 抖音 | `pnpm --filter weapp-sqlite-demo-weapp-vite build:tt` | `dist/tt` |
| 百度 | `pnpm --filter weapp-sqlite-demo-weapp-vite build:swan` | `dist/swan` |
| 京东 | `pnpm --filter weapp-sqlite-demo-weapp-vite build:jd` | `dist/jd` |
| 小红书 | `pnpm --filter weapp-sqlite-demo-weapp-vite build:xhs` | `dist/xhs` |

| 目录 | 框架 | 小程序构建 | Web 构建 |

## 验证流程

先运行各 demo 的 wiring 测试和类型检查，再运行目标构建：

```bash
pnpm --filter weapp-sqlite-demo-weapp-vite test
pnpm --filter weapp-sqlite-demo-taro test
pnpm --filter weapp-sqlite-demo-uni-app test
pnpm --filter weapp-sqlite-demo-mpx test
```

正式链路使用根目录命令构建 Web 和六个小程序目标：

```bash
pnpm acceptance:build
pnpm acceptance:web
pnpm acceptance:debug:web
pnpm acceptance:devtools:doctor
pnpm acceptance:devtools
pnpm acceptance:debug:devtools
pnpm acceptance:mobile:prepare
pnpm acceptance:verify
```

`acceptance:build` 构建 Web 和六个小程序目标，但正式运行证据首期只汇总 Web、微信 DevTools、微信 iOS/Android，以及 Web/微信数据工作台报告。其余五端保持可构建和结构化 `unsupported`，不据此宣称运行支持。正式准备与汇总必须在干净工作区运行。

## 支持等级

| 证据 | 能说明什么 |
| --- | --- |
| 可构建 | 编译器能生成目标产物，不代表宿主能运行 |
| 协议预检 | adapter 能返回稳定能力结果，仍不代表真实设备可用 |
| 官方 DevTools | 目标开发者工具中的行为已验证 |
| iOS/Android 真机 | 对应宿主版本和设备组合已验证，才能进入正式支持矩阵 |

当前正式运行结论以真实 DevTools 和真机报告为准。缺少任一必需证据的平台保持 `unsupported`。

## 平台注意事项

- Web 使用 `@weapp-sqlite/web` 的 IndexedDB 二进制持久化，不回退到内存。
- 应用通过 `@weapp-sqlite/weapp-vite/runtime` 调用统一 API，不显式传入平台、runtime 或 WASM 路径。
- 微信使用 `WXWebAssembly` 路径式实例化；其余小程序目标能力不足时返回 `unsupported`。
- full 的 Web 产物只包含 `sql-wasm-browser.wasm`，小程序产物只包含 `sql-wasm.wasm`；lite 使用 `sql-wasm-lite.wasm`。`variant` 对所有目标生效，`weappPackage` 只改变微信资源归属。
- 微信普通分包通过静态 `require.async()` 按需下载；独立分包不能作为 SQLite 引擎目标。
- `probe()` 会检查文件系统、用户目录、TypedArray、WebAssembly 和包内资源；失败时统一返回结构化错误，不回退内存。
- Headless 结果只是逻辑预检。首期只有 Web 与微信进入正式支持矩阵。

## 常见问题

### 为什么微信和 Web 要分别构建？

Web 需要浏览器 WASM 和 IndexedDB；微信需要 `WXWebAssembly`、代码包里的 WASM 和用户目录文件。插件会只注入当前目标需要的资源。

### 为什么同一个微信包能验收 iOS 和 Android？

小程序包属于微信宿主，系统差异由微信客户端和基础库提供。验收时使用同一份微信产物，分别记录设备、系统、微信版本和 SDKVersion。

### 看到 `unsupported` 是否会自动使用内存数据库？

不会。静默回退会造成重启后数据消失，正式实现会返回结构化错误，让应用明确显示不可用原因。

### 导入文件过大怎么办？

调试控制器有导入字节数和行数上限。先缩小文件或分批导入；不要通过关闭限制来绕过宿主包体积和内存约束。

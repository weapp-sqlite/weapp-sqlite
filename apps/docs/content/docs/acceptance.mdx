## 支持矩阵

每个平台只生成一份小程序产物。开发者工具、iOS 和 Android 的差异来自宿主环境，不生成系统专属小程序包。“内置 adapter”只代表协议实现存在，不等于真实宿主证据已经完成。

## 自动验收

开发调试面板只在 `WEAPP_SQLITE_DEBUG=1` 的构建中启用。Web 面板可下载和选择 `.sqlite` 快照；微信面板的二进制导出通过 DevTools bridge 保存为验收 artifact。`pnpm acceptance:debug:web` 和 `pnpm acceptance:debug:devtools` 分别验证两端的数据预览、分页、查询、写入、导出、导入和持久化。生产 Web/微信构建必须确认调试页面、写 SQL 和导入 API 不在产物中。

Web suite 对生产静态产物执行重置、首次运行、刷新和持久化验证，并把 console error、资源失败和未捕获异常作为硬失败。DevTools suite 在整个文件中只启动一次 automator，使用 `reLaunch('/pages/index/index')` 和 Page data 中版本化的 `acceptance` 对象断言。

Headless 只用于逻辑预检，不计入任何平台支持证据。截图用于保存证据，不做跨系统像素比较。

## 真机验收

真机报告必须绑定 commit SHA、平台、宿主 App、设备、OS 和 SDK 版本。每组环境执行：扫码进入、重置、首次运行、截图、完全退出小程序、重新进入、验证持久化、填写设备与版本信息。

最低版本从候选环境向上测试，第一组完整通过的 OS、微信客户端和基础库组合才能记录为技术最低支持版本。当前最新稳定版本也必须通过。

## 发布门禁

`pnpm acceptance:verify` 只汇总属于当前 commit 的证据。任一纳入正式支持的平台缺少官方 DevTools、iOS 或 Android 报告，或存在检查失败、设备信息为空和截图缺失，都不得在支持矩阵标记通过。

截至 2026-08-26，Web 与真实微信 DevTools 自动验收已在本地通过，微信使用基础库 2.13.0 起提供的 `WXWebAssembly` 路径式实例化能力。四组真机证据尚未完成；因此仓库目前仍没有一次完整门禁通过记录，不能发布“微信 iOS/Android 已支持”的结论。

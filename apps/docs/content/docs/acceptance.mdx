## 支持矩阵

| 目标 | 可构建 | 内置 driver | 正式运行证据 | 当前结论 |
| --- | --- | --- | --- | --- |
| Web | 是 | IndexedDB | Playwright 生产产物 | 自动验收已建立 |
| 微信开发者工具 | 是 | 微信文件系统 + `WXWebAssembly` | 真实 DevTools automator | 自动验收已通过 |
| iOS 微信下限/最新 | 同一微信产物 | 微信文件系统 | 两份真机报告 | 待验收 |
| Android 微信下限/最新 | 同一微信产物 | 微信文件系统 | 两份真机报告 | 待验收 |
| 支付宝、抖音、百度、京东、小红书 | 是 | 无 | `unsupported` 合约测试 | 不宣称运行支持 |

微信只生成一份产物。开发者工具、iOS 和 Android 的差异来自宿主环境，不需要也不允许生成系统专属小程序包。

## 自动验收

Web suite 对生产静态产物执行重置、首次运行、刷新和持久化验证，并把 console error、资源失败和未捕获异常作为硬失败。DevTools suite 在整个文件中只启动一次 automator，使用 `reLaunch('/pages/index/index')` 和 Page data 中版本化的 `acceptance` 对象断言。

Headless 只用于逻辑预检，不计入微信支持证据。截图用于保存证据，不做跨系统像素比较。

## 真机验收

`pnpm acceptance:mobile:prepare` 在干净工作区生成一个微信预览二维码、四份绑定 commit SHA 的报告模板和证据目录。每组环境执行：扫码进入、重置、首次运行、截图、完全退出小程序、重新进入、验证持久化、填写设备与版本信息。

最低版本从候选环境向上测试，第一组完整通过的 OS、微信客户端和基础库组合才能记录为技术最低支持版本。当前最新稳定版本也必须通过。

## 发布门禁

`pnpm acceptance:verify` 要求以下六份报告全部属于当前 commit 且通过：Web、DevTools、iOS 下限、iOS 最新、Android 下限、Android 最新。任一报告缺失、检查失败、设备信息为空、截图缺失或工作区不干净都会返回失败。

截至 2026-08-26，Web 与真实微信 DevTools 自动验收已在本地通过，微信使用基础库 2.13.0 起提供的 `WXWebAssembly` 路径式实例化能力。四组真机证据尚未完成；因此仓库目前仍没有一次完整门禁通过记录，不能发布“微信 iOS/Android 已支持”的结论。

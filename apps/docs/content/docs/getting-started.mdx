## 你将完成什么

完成本页后，你会得到一个名为 `app.sqlite` 的本地数据库，创建 `notes` 表，插入一条数据，并能在 Web 或微信构建中复用同一套业务代码。

## 前置条件

- Node.js 22.12 或更高版本。
- pnpm 11（仓库开发使用的包管理器）。如果你使用 npm，可把 `pnpm add` 换成 `npm install`。
- 一个已经能运行的 weapp-vite 项目。
- 验收微信构建时，需要登录微信开发者工具；真机验收还需要对应 iOS/Android 设备。

## 安装

weapp-vite 项目只需要安装统一集成包：

```bash
pnpm add @weapp-sqlite/weapp-vite
```

npm 等价命令：

```bash
npm install @weapp-sqlite/weapp-vite
```

在 Vite 配置中注册插件。这个插件会根据当前目标注入 runtime，并复制正确的 WASM 文件：

```ts
import { weappSqlite } from '@weapp-sqlite/weapp-vite'
import { defineConfig } from 'weapp-vite'

export default defineConfig({
  plugins: [weappSqlite()],
})
```

底层的 core、WASM、Web 和小程序 adapter 仍可供高级集成直接使用。

## 定义迁移

把迁移放在业务代码可以复用的位置，例如 `src/sqlite.ts`：

```ts
import type { SqliteMigration } from '@weapp-sqlite/core'

export const migrations = [
  {
    version: 1,
    name: 'create_notes',
    up: transaction => transaction.exec(
      'CREATE TABLE notes (id INTEGER PRIMARY KEY, body TEXT NOT NULL)',
    ),
  },
] satisfies readonly SqliteMigration[]
```

版本号必须是正整数且唯一。已经发布的版本不要重写；需要改表时新增更高版本的迁移。

## 打开数据库

```ts
import { openSqlite } from '@weapp-sqlite/weapp-vite/runtime'

import { migrations } from './sqlite'

const database = await openSqlite({
  name: 'app.sqlite',
  migrations,
})

await database.exec('INSERT INTO notes (body) VALUES (?)', ['hello'])
const result = await database.query<{ id: number, body: string }>('SELECT id, body FROM notes')
await database.close()
```

第一次打开时，`openSqlite()` 会加载已有快照并执行未完成的迁移。预期结果是 `notes` 表存在，查询返回刚插入的 `hello`。

所有数据库方法都是异步的。事务回调成功才提交，抛错会自动回滚：

```ts
await database.transaction(async transaction => {
  await transaction.exec('INSERT INTO notes (body) VALUES (?)', ['事务中的数据'])
})
```

`close()` 会先 flush 脏数据，再关闭连接并释放同名连接注册；再次打开会从持久化存储重新加载。

## 在页面中显示结果

把数据库初始化放在页面或应用服务中，处理 loading、ready 和 failed 状态，不要假设浏览器或小程序一定具备 SQLite 能力：

```ts
try {
  const database = await openSqlite({ name: 'app.sqlite', migrations })
  const result = await database.query<{ id: number, body: string }>(
    'SELECT id, body FROM notes ORDER BY id DESC',
  )
  console.log(result.rows)
}
catch (error) {
  console.error(error)
}
```

## 加载 WASM

`weappSqlite()` 在构建时读取 weapp-vite 的单目标元数据并发射 WASM。Web 只包含 `sql-wasm-browser.wasm`，小程序只包含 `sql-wasm.wasm`；应用不需要维护资源路径、平台 runtime 或复制脚本。

## 启用数据工作台

```ts
export default defineConfig({
  plugins: [weappSqlite({
    debug: {
      enabled: process.env.WEAPP_SQLITE_DEBUG === '1',
      page: {
        route: '__weapp_sqlite_debug/index/index',
        configFile: './src/sqlite-debug.config.ts',
      },
    },
  })],
})
```

```ts
// src/sqlite-debug.config.ts
export default defineSqliteDebugWorkspace({ databaseName: 'app.sqlite', migrations })
```

生成页通过自动路由进入独立分包。应用清单使用 `app.json.ts` 时，从 `weapp-vite/auto-routes` 导入 `subPackages`：

```ts
import { subPackages } from 'weapp-vite/auto-routes'
import { defineAppJson } from 'weapp-vite/json'

export default defineAppJson({ pages: ['pages/index/index'], subPackages })
```

`WEAPP_SQLITE_DEBUG` 未启用时不会生成页面，`subPackages` 为空，管理代码和文件 API 会被构建器剔除。完整操作说明见[调试工作台](./debug-workbench)。

## 遇到错误怎么办

- `SQLITE_RUNTIME_UNSUPPORTED`：当前宿主缺少文件系统、WebAssembly 或 TypedArray 能力。
- `SQLITE_ENGINE_INIT_FAILED`：WASM 初始化失败，先检查目标构建是否包含正确的资源。
- `SQLITE_OPEN_OPTIONS_CONFLICT`：同名数据库已经打开，但迁移或 adapter 配置不同。
- 调试路由冲突：检查 `src` 下是否已有 `__weapp_sqlite_debug` 目录。

先记录结构化错误的 `code` 和 `message`，再对照[多端接入](./multi-platform)和[支持矩阵](./acceptance)排查。

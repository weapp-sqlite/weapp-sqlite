## 构建模型

文档站使用 Next.js 的 `output: 'export'`。Fumadocs 在构建期读取 MDX、生成页面、搜索索引、Markdown 文本和 Open Graph 图片，部署产物位于 `apps/docs/out`。线上 Worker 只转发静态资产，不执行 React、Next SSR 或动态 API。

```bash
pnpm --filter @weapp-sqlite/docs build
pnpm --filter @weapp-sqlite/docs preview
```

`trailingSlash: true` 会让文档页面输出为 `docs/getting-started/index.html`，Cloudflare Static Assets 可以直接按目录 URL 提供这些文件。

## Cloudflare Worker

`apps/docs/wrangler.jsonc` 将 `out` 绑定为 `ASSETS`，域名配置为 `sqlite.weapp.dev`。Worker 的唯一职责是：

```ts
export default {
  fetch(request, env) {
    return env.ASSETS.fetch(request)
  },
}
```

部署前先确认 Cloudflare 登录状态，然后执行 dry-run：

```bash
pnpm --filter @weapp-sqlite/docs wrangler:types
pnpm --filter @weapp-sqlite/docs run deploy:dry
pnpm --filter @weapp-sqlite/docs run deploy
```

首次部署需要当前 Cloudflare 账号对 `weapp.dev` 有 DNS / Custom Domain 权限。若账号未登录或域名不在当前账号，Wrangler 会在部署阶段明确报错；这不影响本地静态构建和预览。

## GitHub Actions 自动部署

仓库提供 `.github/workflows/docs-deploy.yml`。推送到 `main` 且修改文档站、包 README、锁文件或该 workflow 时，会自动构建并部署；也可以在 GitHub Actions 页面手动选择 **Deploy Docs → Run workflow**。

在仓库的 **Settings → Secrets and variables → Actions** 中配置以下两个 repository secrets：

- `CLOUDFLARE_API_TOKEN`：仅授予 Workers 部署和读取账号信息所需权限的 API Token。
- `CLOUDFLARE_ACCOUNT_ID`：目标 Cloudflare 账号 ID。

Token 不写入仓库、workflow 日志或本地配置。部署 job 使用 `pnpm install --frozen-lockfile`、Node.js 22.12 和 `wrangler deploy`，构建失败或 dry-run 校验失败时不会执行正式部署。

Cloudflare 侧还需要满足两个前置条件：`weapp.dev` zone 在该账号下，且 Worker `weapp-sqlite-docs` 已允许绑定 `sqlite.weapp.dev` Custom Domain。首次绑定域名可能需要在 Cloudflare 控制台确认 DNS；绑定完成后，部署结果应在 [sqlite.weapp.dev](https://sqlite.weapp.dev) 可访问。

## 发布后检查

部署完成后，在 Actions 运行详情确认 `Build documentation`、`Validate deployment configuration` 和 `Deploy to Cloudflare Workers` 三步均通过，然后检查：

- [首页](https://sqlite.weapp.dev/)
- [快速开始](https://sqlite.weapp.dev/docs/getting-started/)
- [核心概念](https://sqlite.weapp.dev/docs/concepts/)
- [调试工作台](https://sqlite.weapp.dev/docs/debug-workbench/)

如果出现 404，先确认域名 Custom Domain 已绑定，再检查 `apps/docs/out` 是否包含对应的 `index.html`；如果 workflow 在认证阶段失败，检查两个 Secrets 的名称、账号 ID 和 Token 权限，不要把 Token 粘贴到 issue 或聊天中。

## 静态资源检查

部署前应确认以下文件存在：

- `apps/docs/out/index.html`
- `apps/docs/out/docs/index.html`
- `apps/docs/out/docs/getting-started/index.html`
- `apps/docs/out/api/search.json`（搜索索引的实际路径以构建输出为准）

这个站点不承载 SQLite 数据库，也不需要 Worker binding。应用中的 `sql-wasm.wasm` 仍由各个小程序或 Web demo 自己打包。

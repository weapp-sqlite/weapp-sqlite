## 构建模型

文档站使用 Next.js 的 `output: 'export'`。Fumadocs 在构建期读取 MDX、生成页面、搜索索引、Markdown 文本和 Open Graph 图片，部署产物位于 `apps/docs/out`。线上 Worker 只转发静态资产，不执行 React、Next SSR 或动态 API。

```bash
pnpm --filter @weapp-sqlite/docs build
pnpm --filter @weapp-sqlite/docs preview
```

`trailingSlash: true` 会让文档页面输出为 `docs/getting-started/index.html`，Cloudflare Static Assets 可以直接按目录 URL 提供这些文件。

## Cloudflare Worker

`apps/docs/wrangler.jsonc` 将 `out` 绑定为 `ASSETS`，域名配置为 `sqlite.weapp.dev`。Worker 的唯一职责是：

```ts
export default {
  fetch(request, env) {
    return env.ASSETS.fetch(request)
  },
}
```

部署前先确认 Cloudflare 登录状态，然后执行 dry-run：

```bash
pnpm --filter @weapp-sqlite/docs wrangler:types
pnpm --filter @weapp-sqlite/docs run deploy:dry
pnpm --filter @weapp-sqlite/docs run deploy
```

首次部署需要当前 Cloudflare 账号对 `weapp.dev` 有 DNS / Custom Domain 权限。若账号未登录或域名不在当前账号，Wrangler 会在部署阶段明确报错；这不影响本地静态构建和预览。

## Cloudflare Workers Builds 自动部署

生产部署由 Cloudflare Workers Builds 直接监听 GitHub 仓库完成。GitHub Actions 仍然只负责测试和验收，部署状态以 Cloudflare Dashboard 中的 Build 和 Active Deployment 为准。

在 Cloudflare Dashboard 的 **Workers & Pages → `weapp-sqlite-docs` → Settings → Builds** 中配置：

| 配置项 | 值 |
| --- | --- |
| GitHub repository | `weapp-sqlite/weapp-sqlite` |
| Production branch | `main` |
| Root directory | `/`（仓库根目录） |
| Build command | `pnpm install --frozen-lockfile && pnpm --filter @weapp-sqlite/docs build` |
| Deploy command | `pnpm --filter @weapp-sqlite/docs exec wrangler deploy` |
| Node.js | `22.13.0` 或更高的 Node 22 版本 |
| Worker | `weapp-sqlite-docs` |

Workers Builds 会使用 Cloudflare 控制台中自动生成或选择的 API Token。Token 由 Cloudflare 管理，不需要创建 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` GitHub Secrets，也不应把 Token 写入仓库。

### 构建触发范围

生产分支只使用 `main`。建议在 Workers Builds 的 **Build watch paths** 中包含以下路径：

- `apps/docs/**`
- `packages/*/README.md`
- `README.md`
- `pnpm-lock.yaml`
- `apps/docs/wrangler.jsonc`
- `package.json`、`pnpm-workspace.yaml`

这样只有会影响文档内容、依赖或 Worker 配置的提交才会触发部署。其他源码变更仍由 GitHub CI 检查，但不会重新发布文档站。

Cloudflare 侧还需要满足两个前置条件：`weapp.dev` zone 在当前账号下，且 Worker `weapp-sqlite-docs` 已绑定 `sqlite.weapp.dev` Custom Domain。首次绑定域名可能需要在 Cloudflare 控制台确认 DNS；绑定完成后，部署结果应在 [sqlite.weapp.dev](https://sqlite.weapp.dev) 可访问。

### 首次部署检查

首次连接仓库后，在 Cloudflare Builds 页面确认以下步骤均成功：

1. 安装依赖完成，且使用 Node.js 22.13 或更高版本。
2. 文档静态构建生成 `apps/docs/out`。
3. `wrangler deploy` 上传 Worker 和 Static Assets。
4. 新版本被提升为 Worker 的 Active Deployment。

如果只上传了版本但没有上线，检查 Deploy command 是否为 `wrangler deploy`，不要改成只上传版本的 `wrangler versions upload`。如果出现 404，先确认 Custom Domain 和 DNS，再检查 `apps/docs/out` 是否包含对应的 `index.html`。

## 发布后检查

部署完成后，在 Cloudflare Builds 运行详情确认构建、部署和 Active Deployment 均成功，然后检查：

- [首页](https://sqlite.weapp.dev/)
- [快速开始](https://sqlite.weapp.dev/docs/getting-started/)
- [核心概念](https://sqlite.weapp.dev/docs/concepts/)
- [调试工作台](https://sqlite.weapp.dev/docs/debug-workbench/)

如果出现 404，先确认域名 Custom Domain 已绑定，再检查 `apps/docs/out` 是否包含对应的 `index.html`；如果 workflow 在认证阶段失败，检查两个 Secrets 的名称、账号 ID 和 Token 权限，不要把 Token 粘贴到 issue 或聊天中。

## 静态资源检查

部署前应确认以下文件存在：

- `apps/docs/out/index.html`
- `apps/docs/out/docs/index.html`
- `apps/docs/out/docs/getting-started/index.html`
- `apps/docs/out/api/search.json`（搜索索引的实际路径以构建输出为准）

这个站点不承载 SQLite 数据库，也不需要 Worker binding。应用中的 `sql-wasm.wasm` 仍由各个小程序或 Web demo 自己打包。
